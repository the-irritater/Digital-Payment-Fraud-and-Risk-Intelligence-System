# Digital Payment Fraud and Risk Intelligence Platform

| Metadata | Details |
| :--- | :--- |
| **Author** | Sanman Kadam |
| **Project** | Real-Time Digital Payment Fraud Detection and Explainable Risk Intelligence Platform |
| **Dataset** | PaySim Synthetic Financial Transactions (Kaggle) |
| **Context** | Reserve Bank of India Payment System Indicators |
| **Primary Metric** | PR-AUC (Average Precision) |

An explainable, cost-sensitive fraud risk platform using PaySim synthetic transaction data, synthetic UPI-like simulations, XGBoost with Optuna optimization, Isolation Forest anomaly detection, behavioral analytics, graph-based risk analysis, and rule-based decisioning.

## India Payment Ecosystem Context

RBI publishes aggregate payment-system statistics and domestic fraud registry data. Key context points:

- **UPI Scale**: NPCI processes hundreds of millions of daily UPI transactions. Exact volumes vary by period (see RBI Payment System Indicators for current figures).
- **Reported vs. Attempted**: RBI statistics capture retrospective bank-reported losses above reporting thresholds. They do not include blocked fraud attempts. Real-time payment gateways require proactive prediction to intercept fraud before settlement.
- **Primary Risk Vectors**: Social engineering phishing, fraudulent collect requests, synthetic KYC mule account rings, and midnight high-velocity drain transfers.

*Source: RBI Annual Reports and Payment System Indicators.*

## Model Performance

Models evaluated on strict temporal test set (train on earlier steps to test on later steps).

### Benchmark Comparison

| Model | PR-AUC | ROC-AUC | Threshold | Precision | Recall | F1 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| Logistic Regression (Baseline) | 0.7959 | — | 0.50 | 0.1840 | 0.7634 | 0.2966 |
| Random Forest | 0.8660 | — | 0.50 | 0.4180 | 0.8817 | 0.5670 |
| **XGBoost (Optuna Tuned)** | **0.9515** | **0.9964** | **0.17** | **0.3100** | **1.0000** | **0.4733** |

> **Interpreting the XGBoost result**: At the cost-optimized operating threshold of 0.17, the model detected 100% of observed test-set fraud cases (186/186), with 31% precision. The low threshold favors recall over precision. This is a deliberate operating-point choice for fraud detection, where missing a fraud is far more costly than investigating a legitimate transaction. See `reports/threshold_cost_table.csv` for the full threshold-cost tradeoff analysis.

### Financial Loss Model

Financial loss uses **actual transaction amounts** of missed frauds:

```text
Loss = sum(actual_amount of each missed fraud) + (false_positive_count * 200 investigation cost)
```

See [reports/model_card.md](reports/model_card.md) for detailed model provenance, known limitations, and intended use.

## Hybrid Risk Engine

The Risk Engine synthesizes three analytical components into a **composite Risk Score (0 to 100)**:

```text
Risk Score = (ML_prob * 100 * 0.60) + (Anomaly_score * 100 * 0.20) + (Rule_score * 0.20)
```

| Component | Scale | Weight | Description |
| :--- | :---: | :---: | :--- |
| XGBoost Probability | 0 to 1 -> 0 to 100 | 60% | Supervised fraud probability |
| Isolation Forest Score | 0 to 1 -> 0 to 100 | 20% | Normalized anomaly score |
| Business Rules | 0 to 100 | 20% | Deterministic rule triggers |

### Risk Tiers and Decision Actions

| Risk Score | Tier | Action | Description |
| :---: | :---: | :---: | :--- |
| 0 to 30 | LOW | ALLOW | Automated payment approval |
| 31 to 60 | MEDIUM | REVIEW | Step-up authentication |
| 61 to 80 | HIGH | REVIEW | Escalated analyst review and enhanced authentication |
| 81 to 100 | CRITICAL | BLOCK | Transaction blocked; escalate account for investigation |

## Synthetic UPI and Graph Risk Analysis

- **Synthetic UPI Generator**: Creates transactions from three behavioral personas (Normal, Suspicious, Mule) with distinct statistical distributions for amounts, velocity, device changes, and beneficiary churn.
- **Graph Risk Analysis**: Uses NetworkX to compute structural features (PageRank, degree centrality, connected components) that correlate with money mule network topologies. These are structural risk indicators, not proof of fraud.

```bash
pytest tests/ -v
```

### 4. Launch Streamlit Dashboard
```bash
streamlit run app/streamlit_app.py
```
